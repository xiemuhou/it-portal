# IT 门户文档导航与维护说明

这份文件帮助你快速找到正确文档，并说明各文档之间的边界。部署人员不需要阅读业务需求的全部细节，普通员工也不需要阅读数据库迁移命令。

## 1. 按角色选择文档

| 你的角色 | 先读 | 需要时再读 |
|---|---|---|
| 普通员工 | `IT门户系统操作手册_v1.0.md` 第 1～6 节 | 工单、知识库相关 FAQ |
| IT 运维 | 系统操作手册、`五类台账使用说明.md` | 需求规格说明书中的字段规则 |
| 门户管理员 | 系统操作手册第 12 节 | 需求规格说明书、备份恢复手册 |
| Windows 管理员 | `Windows部署与启停手册.md` | `数据库与门户迁移恢复手册.md` |
| Linux 管理员 | `Linux快速部署手册.md` | 架构审计报告、数据库恢复手册 |
| DBA | 数据库迁移与完整恢复手册 | Linux 手册第 2、5 节 |
| 开发维护人员 | README、需求规格说明书 | 开发与部署说明、架构审计报告 |

## 2. 文档职责

| 文档 | 权威范围 | 不负责的内容 |
|---|---|---|
| `README.md` | 项目概览、部署路径选择、文档入口 | 不展开全部命令和字段 |
| `IT门户系统需求规格说明书_v1.0.md` | 功能边界、业务规则、权限和验收 | 不作为安装教程 |
| `IT门户系统操作手册_v1.0.md` | 浏览器页面操作 | 不描述服务器内部实现 |
| `Windows部署与启停手册.md` | Windows + SQL Server 部署运行 | 不描述 MySQL 迁移 |
| `Linux快速部署手册.md` | Linux + MySQL、systemd、Nginx、跨库迁移 | 不描述日常页面操作 |
| `数据库与门户迁移恢复手册.md` | SQL Server 备份、恢复和完整恢复批次 | 不替代 Linux 跨库迁移章节 |
| `五类台账使用说明.md` | 网络台账字段、状态和关联关系 | 不描述部署 |
| `IT门户系统架构审计报告_2026-10-21.md` | 某一审计时点的风险和优化建议 | 不代表当前实时运行状态 |
| `新版开发与部署说明.md` | 历史交付与实现记录 | 不作为首选操作入口 |

## 3. 当前正式支持路径

1. Windows + SQL Server：保留现有生产环境，使用 `portal.bat` 管理。
2. Linux + MySQL：使用 systemd 管理，项目目录为 `/opt/it-portal`。
3. 全新数据库：通过 Alembic 自动创建表结构。
4. SQL Server → MySQL：使用 `portal.migrate_database`，同时迁移整个 `data/business/`。

其他操作系统与数据库组合即使底层驱动可能可用，也不属于当前主要验收路径。

## 4. 修改文档时的规则

- 功能行为变化：先更新需求规格说明书，再更新操作手册。
- 页面字段或导入模板变化：同步更新操作手册和对应台账说明。
- 部署命令变化：更新对应操作系统手册，并在 README 保留简短入口。
- 数据库迁移版本变化：更新 Linux 手册中的版本兼容说明和故障处理。
- 备份边界变化：同步更新 README、部署手册和恢复手册。
- 架构审计报告是历史快照，不直接改写旧结论；需要重新审计时新建带日期的报告。

## 5. 交付前检查

- README 中的文档链接可以打开；
- Windows 和 Linux 命令没有混用路径分隔符；
- 默认端口统一为 `8089`；
- 配置示例不包含真实账号密码、内网地址或 API 密钥；
- 数据库备份和 `data/business/` 文件备份都被明确说明；
- 全新部署与数据迁移的启动顺序没有混淆；
- 文档没有把上传到某个代码托管平台作为项目部署前提。
