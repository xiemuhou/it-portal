# 数据库版门户：开发交付与部署

日期：2026-10-16，2026-10-28 更新。当前生产目标为 Linux、systemd、MySQL 8 和数据库版门户，默认端口为 `8089`。Windows/SQL Server 运行方式保留用于现有环境和迁移回退；旧 `server.py` / 8088 原型、Excel/OneDrive 同步入口及相关静态资源已清理。

## 已接通的功能

- 账号登录、本人改密、管理员新增/修改/停用/设置密码、删除身份资料并匿名化；新建即能登录，密码至少 8 位。
- 会话最长 8 小时、空闲 10 分钟；后台检查不续空闲。CSRF、哈希凭据、改密失效、最后管理员保护。
- 自定义角色，模块操作及本人/当前负责/指定站点/部门/全部范围；服务端统一鉴权，相关权限下一请求生效。
- 工单描述提交、未接单更正、接单即计时、预分派/转派、分类并选择实际结束时间后直接关闭；员工可直接重开，新轮次单独计时。申请人和 IT 留言，内部备注与附件单独鉴权。
- 工单分类/人员汇总，轮次数和去重工单数、总/平均历时、分段参与量及个人分段历时；显示口径与等待时间说明。
- 数据库内在线维护设备、线路、VLAN、子网、Wi-Fi、VPN、合同及其关联参数，站点/部门/供应商/分类等基础资料。设备等主资源支持基本信息和类型参数同事务保存。
- 支持维护模块的标准 XLSX 模板下载、校验预览、版本冲突、确认提交、明确仅提交正确行、同批次重试去重及导出。首版通用模板针对基础资料/台账/公告等；用户批量模板、历史工单模板尚未接通，不应将任意旧 Excel 直接上传。
- 管理员首页公告，置顶、发布、截止时间及撤下；公开端只显示有效已发布内容。
- 知识上传/复制原目录文件为草稿、版本、发布/撤下。HTML 在沙箱中按原排版打开；已有 HTML 引用的受支持本地资源在接入时快照；PDF/PPT 连续阅读，在新窗口打开，无门户翻页或源文件下载按钮。PPT 转换仍依赖 PowerPoint/LibreOffice，发布前检查预览。
- 问题描述推荐接口 `/api/knowledge/recommendations` 提供本地关键词匹配；提单页已接入可选的 OpenAI 兼容 AI 对话。管理员通过“AI 助手设置”配置完整 Chat Completions 地址、模型与密钥，未启用时不发送外部数据，调用失败不阻止提单。
- 站内消息、操作审计；数据库备份不由门户执行，交由 SQL Server Agent、维护计划或企业备份平台管理。

知识元数据编辑/删除、用户批量模板、历史工单模板、报表文件导出、资源跨关系的全部专用一致性校验和合同到期定时提醒仍需后续完善。SQL Server→MySQL 已提供离线迁移、空目标保护、事务回滚和逐表摘要校验，但正式切换前仍必须完成真实 MySQL 环境验收。

## 本地启动与账号

```powershell
.\portal.bat foreground
```

需要 Python 3.10+；脚本使用项目 `.venv`，首次安装 `requirements-business.txt`。也可运行 `.\.venv\Scripts\python.exe -m portal --port 8089`。

未配置外部数据库时使用 **data/business/business.db**；不会降级到原 portal.db，也不会在 SQL Server 连接失败时悄悄回退。页面底部明确显示本地验证库。

首次管理员为 `admin`，随机密码在 **data/business/initial-account.txt**。如启动前设置 `IT_PORTAL_BOOTSTRAP_PASSWORD`，则使用该值且不生成明文交付文件。此变量只在首次初始化有效；不会重置现有账号。账号交接后移除交付文件，用户可自行改密。

初始字典只有 IT 部门、外仓及别名、常见问题分类、通用知识分类和初始角色；无示例工单、公告、设备或手册冒充正式数据。可先登录管理员建立组织和用户，接入已有知识文件，再逐步维护台账。

## 配置 SQL Server itPortal

部署时应配置实际 SQL Server 地址和端口（例如 `db.example.local:1433`）以及独立数据库名 `itPortal`。数据库账号只写入受控服务器上的本机配置。生产环境应保持加密连接并验证服务器证书；如内网临时使用证书信任例外，必须经过管理员明确审批。文档不得保存数据库口令。

1. 在数据库服务器准备独立业务库 `itPortal`，不指向已有其他业务库。确认实际 TCP 端口、网络可达性和 SQL Server 认证账号。
2. 将 `business.example.json` 复制为 **business.local.json**，在本机填写 username/password，保留已确认的 1433 端口和 itPortal 库名。该文件已忽略提交；不要截图或将含口令配置发到聊天。填写完成并初始化数据库后再重启新版切换连接。
3. 配置使用已安装驱动。TLS 默认启用并验证证书；本地测试若使用自签证书，应按公司部署规则配置受信任证书。`secure_cookie` 在 HTTPS 部署时设为 true。
4. 先备份并检查目标为空的新业务库，再用具备 DDL 权限的部署账号运行：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m portal.manage init-admin
.\portal.bat foreground
```

应用连接信息也可由进程环境变量 `IT_PORTAL_DATABASE_URL` 提供，优先于本机配置。不要把带密码的连接字符串写进命令历史、任务说明或版本库。

真实 SQL Server/MySQL 使用 Alembic 建库，不在 Web 启动时自动执行 `create_all`；本地 SQLite 为开发方便自动建表。历史迁移保持不可变，结构调整只能新增 Alembic 版本。SQL Server 现有环境已经过业务验证；MySQL 模型、迁移 SQL 和跨数据库传输逻辑已完成自动化验证，但正式目标实例的连接、字符集、负载、备份恢复和文件权限仍属于上线验收项。

## 数据库备份边界

门户不提供数据库备份菜单、下载或恢复接口。SQL Server 使用 SQL Server Agent、维护计划或企业备份平台；MySQL 使用受控的 `mysqldump` 或企业备份平台。门户数据库账号不需要 `BACKUP DATABASE`、`RESTORE` 或 SQL Agent 管理权限。

数据库备份不包含知识原件、知识资源、公告附件、工单附件和本地加密密钥。完整灾难恢复必须在同一批次保护数据库和 `data/business/`，并在隔离环境执行恢复演练。

## Linux / MySQL

Linux 生产环境使用 MySQL 8.0/8.4、Python 3.10+、systemd 和可选 HTTPS 反向代理。PPT/PPTX 预览使用 LibreOffice 和服务器中文字体，不依赖 PowerPoint COM 或 Windows 盘符。

配置`database.engine`为`mysql`，设置实际主机、端口、库名和管理员准备的root账号；数据库统一使用`utf8mb4`。systemd单元位于`deploy/systemd/it-portal.service`，每次启动前自动执行Alembic升级和幂等管理员初始化。`python -m portal.migrate_database`用于把停止写入的SQL Server源库迁入Alembic已初始化的空MySQL，保留业务主键和哈希并逐表校验；详细步骤见《Linux快速部署手册》。

MySQL由管理员使用`mysqldump --single-transaction --quick --routines --triggers`或企业备份平台保护；密码通过`mysql_config_editor`、权限为`0600`的受控配置或备份平台提供，不能写进命令历史。数据库与`/opt/it-portal/data/business`文件必须形成同一恢复批次。
